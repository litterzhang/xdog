# v2.3.2 GitHub test failures: controlled scheduling investigation

Date: October 12, 2026. Investigation baseline: `v2.3.2`, commit
`5a8ec52eb8c09f504a4fc82af67ff9dee1bff35b`. Current release commit:
`0331e1733badb399a4205f9accff590b13257d69` (`v2.4.0`).

This investigation does not move either tag, restart a live service, retry a
release, or install dependencies. The proposed fixes are local/uncommitted.

## GitHub evidence

Downloaded using the authenticated `gh` CLI and the existing proxy:

| Run | Workflow | Result |
| --- | --- | --- |
| 38201095080 | main CI at v2.3.2 commit | 2 failed, 8122 passed, 149 skipped |
| 38201095103 | v2.3.2 publish | 3 failed, 8121 passed, 149 skipped; six builds passed, publishing/release skipped |

The two runs overlap in one failure, producing four distinct failure scenarios:

1. `test_mcp_task_hosts.py`: required-tool refusal, Claw panel still busy.
2. `test_mcp_task_terminal.py`: cancelled elicitation, Coding or Claw already
   received a `tasks/result` error before the pre-cancel assertion.
3. `test_rpc_child_terminal.py`: CLI exits normally but no model `.settled` marker.
4. `test_terminal_acceptance.py`: Claw literal completion unavailable on a later draft.

These are Linux cases, not deferred Windows/macOS cases. The GitHub runners used
CPython 3.12.3; local controlled replays use the existing Linux CPython 3.13.12
workspace environment. No claim is made that the full hosted environment or its
precise historical interleaving has been reproduced.

## 1. MCP result is not UI settlement

`McpPanel._answer_sampling()` removes the input review immediately and keeps
`_busy=True` while validation and teardown settle. `sampling_closed` clears busy.
For Claw, transport task replies and UI events are delivered on independent
paths; receiving a `tasks/result` error does not prove the UI received its close.
The old predicate waited only for `sampling_review is None`, which was already
true before settlement, and then asserted `not _busy`.

A controlled replay withheld only `sampling_closed`, leaving the real worker and
peer-result transport active. It reproduces the exact busy assertion on the
actual v2.3.2 sources. The new `test_mcp_task_ci_ordering.py` fails against that
old predicate and passes after it waits for both no review **and** not busy.

No runtime event semantics or timeout limits changed. The model-call, empty
history, required-tool error, parent-draft, permission and group-idle assertions
remain in place.

## 2. Cancellation and the physical observer raced

The legacy task fixture asks for `tasks/result` immediately after creation and
cancels as soon as it sees `input_required`. Cancellation is allowed to produce
an error response before the test's next tmux capture. The old assertion demanded
no `retrieve` response at a point it treated as pre-cancel, without controlling
when cancellation was admitted.

Slowing only the test observer until the cancellation error has arrived
reproduces this assertion on v2.3.2. The GitHub compound assertion did **not**
prove a `PRIVATE` leak: its printed task record contained no private value; the
failing conjunct was the already-present `retrieve` row.

The fixture now accepts an optional, private cancellation gate. Physical tests:

1. Assert creation metadata is secret-free and retrieval is still withheld.
2. Explicitly open the cancellation gate.
3. Check peer cancellation identity and status.
4. Check the retrieval response is error `-32000`, has no success result, and no
   frame contains the private sentinel.
5. Keep model-call, restored parent editor, cursor, terminal and teardown checks.

The gate is bounded and released in `finally`; it is a fixture-only ordering
primitive, not a delay added to production or a blanket timeout increase. Other
users of the fixture retain its immediate-cancel mode.

## 3. Child terminal registration is not model entry

The child extension terminal registry becomes active before the child prompt's
input/context/checkpoint processing reaches the provider generator. Only a
**generator that actually entered** writes the fixture's `.settled` marker in
its `finally`. Cancelling before model entry legitimately produces neither the
model-entry marker nor its model-cleanup marker.

Holding the real child's pre-model context boundary reproduces the missing
`.settled` assertion with exit 0 on **both** v2.3.2 and v2.4.0. The persisted child
is canceled and no longer settling. Requiring actual model entry before testing
model shutdown passes on both revisions; a never-admitted model fails at the
bounded admission assertion rather than falsely claiming it was cleaned up.

The test now waits for the existing model-entry marker, detects early CLI exit,
and asserts cleanup has not already occurred. All transform receipt, parent
permission/history, exit-0 and post-quit `.settled` assertions remain. No child
lifecycle or Agent implementation change was needed for this demonstrated race.

## 4. Literal completion

The physical test selected a completion, moved to End, then used Undo/End to
restore its earlier draft. Undo and cursor movement trigger **new** completion
requests. Editor paint is not a frontend receipt that those callbacks have settled.
Ctrl-C before settlement cancels the admitted worker invocation. The established
fail-closed contract in `extensions/runtime.py` fails and closes that worker on
cancellation; its later completion registrations disappear rather than being
silently replayed. The next literal menu is therefore unavailable.

The same controlled scheduling gate reproduces the missing third, single-quoted
escaped literal menu using the original test on both archived v2.3.2 and v2.4.0.
The synchronized test passes both. Earlier insertion phases do not issue fresh
callbacks for the accepted text/cursor because the completion feed dismisses that
exact draft; Undo/End changes it and is the demonstrated race window.

The fix reuses the test fixture's existing nonce-bearing **frontend** receipt
observer before clearing each Undo/End draft, not merely a host-idle snapshot.
It preserves all quote/backslash/suffix fidelity, insertion-only, zero command/model
calls, final empty-editor receipt, and terminal restoration assertions. The six
new scheduling cases also check stale response rejection, latest-cursor coalescing,
intentional cancellation revocation versus settlement preservation, and cleanup
of workers, private sockets, PID files and client tasks.

No worker cancellation policy or production callback behavior changed. Controlled
replays establish causal schedules matching the CI symptom, not knowledge of its
unrecorded historical callback timing.

## Parallel-workspace boundary

A separately authorized task (`Prune tests for one-minute runs`) concurrently
removed/refactored many terminal tests while this investigation's integration gate
was executing. Those changes were **not** made by this investigation and were not
restored or overwritten. In particular, the old full literal acceptance test no
longer exists in the shared checkout.

To avoid proving success by removed tests or in-memory imports, the complete seven-file
fix is saved in `/tmp/xdog-ci-investigation-2.3.2/fix.patch` and applied to a private
`git archive HEAD` copy with the original suite. Its explicit file hashes, exact
command and results are separate from the live checkout's pruning. The preserved
patch can be reviewed/backported; do not blindly apply it over a refactored suite.

The current debugging request did not authorize another commit/push, tag movement,
release retry, or service restart. These test fixes are not yet verified by a new
GitHub run; pre-existing v2.4.0 workflows execute the unpatched release commit.

elicitation failure (8457 passed, 149 skipped). Main CI run 38227871874 failed

and these release notes/evidence. Concurrent pruning and pytest concurrency
configuration are excluded; their working changes are preserved. Historical
v2.3.2/v2.4.0 tags remain immutable. Actual publication requires the new workflow
to complete; a tag push alone is not proof the packages reached PyPI.
